# 怎样使用这套安排

先打开仓库根目录的 [统一入口](../LEARNING.md)，再打开 [今天的任务卡](DAILY-PLAN.md)。本地专用工作区位于本仓库的上一级目录，文件名为 AI-Systems-Learning.code-workspace；它已经指向现有课程和Python环境。公开版 [AI-Systems.code-workspace](../AI-Systems.code-workspace) 使用相对目录和PATH中的Python。

## 顺序和时间

| 学习日 | 主线 | 支撑材料 |
| --- | --- | --- |
| D01–D05 | CSE291三份作业集中冲刺 | 只补做题必需的课程内容 |
| D06–D15 | Omni任务、Stage、通信与调度 | C++10天，每天45–90分钟 |
| D16–D23 | SGLang桥接、缓存、服务、测量 | 复用PA2/PA3，选读K8S推理章节 |
| D24–D26 | 最小K8S部署理解与Omni复盘 | 资源、调度、冷启动、可观测性 |
| D27–D40 | 持续读Omni；用小RL任务理解采样与系统机制 | 同步→异步→数值/版本一致性 |
| D41–D42 | 验证、整理和复现 | 汇总既有证据，不再加新课程 |

前5天每天300分钟，其余每天270分钟，共191.5小时计划工作量；不是保证工期。每天只有4小时，可先削减选读和拓展比较，保留主任务、验证与10–15分钟笔记；剩余任务顺延。休息按自己节奏安排。

**PA1/PA2/PA3都从零开始，25小时完成三份作业风险很高。** 日程已覆盖必做范围、暂缓bonus。D5结束逐项检查，未完成就插入补完日，后续日号顺序不变；不要为了日历整齐把失败测试记作完成。课程提交由用户按实际要求完成。

## 每天的固定操作

1. 打开对应Day，按表中的顺序进行，不跳进当天未要求的章节。
2. VS Code菜单“终端 → 运行任务”，选择“学习：生成当天笔记”，输入1–42。
3. 打开学习笔记文件夹的dayNN.md：记录问题、输入输出、观察事实、解释、证据和明日起点。模板其余栏目按需填写。
4. 在 [PROGRESS.md](PROGRESS.md) 记录阅读/已运行/已验证/受阻。代码生成或资料存在，不表示你已学会。

也可在本仓库终端运行：

    python study/tools/note.py --day 1

再次运行只返回已有文件，不覆盖笔记。42份空白笔记已在本地按当天任务预填；GitHub保存的是模板、日程和生成工具。

## 内容存放

| 内容 | 位置与约定 |
| --- | --- |
| 单一日程数据 | schedule.json |
| 每日任务卡 | days/day01.md … day42.md |
| 每日填写内容 | notes/dayNN.md；默认本地保存 |
| 通用模板 | templates/daily-note.md |
| CSE291官方起始代码 | 上一级cse291-assignments；PA1/PA2/PA3各保留原目录与说明 |
| C++工程 | 上一级的cpp-ai-systems-10days；保留原编译/调试任务 |
| RL原始课程 | 上一级的rl-inference-lab；查章节，不再按另一日历执行 |
| Omni教学代码 | 本仓库sglang_omni；按原课程进度逐步提供 |
| Omni上游参考 | 本仓库sglang-omni，只读，固定v0.1.8 |

本机已经有阶段0 Mock与C++示例；本次日程提交不包含此前尚未提交的教学改动。新克隆如果没有本地Mock文件，可先按固定上游源码阅读；不得把任务卡视为所有后续代码已实现。原RL后续实验也多数仍需逐课提供。进入未实现的小课时，围绕当天问题请求讲解和可运行示例，不要求先自己写完整运行时。

CSE291的作业解答、grader凭据、weights和包含答案的笔记留在本地；官方要求不要把解答放公开仓库。notes默认被Git忽略，避免整目录提交时夹带。未来若要分享笔记，可整理为不含课程解答的学习总结，检查后再显式提交。本次没有设置自动上传或定时推送。

## 换电脑与维护

公开工作区假设四个目录并列：SGLang-Omni-FromScratch、cse291-assignments、cpp-ai-systems-10days、rl-inference-lab。CSE291官方起始代码可从SOURCES中的官方仓库获取。缺少某个课程时从工作区删除该文件夹项，仍可阅读全套任务卡、来源和模板；C++工程目前保存在本机，并未由本次同步另建远程仓库。

修改schedule.json之后运行以下命令更新任务卡；它不会改notes中的已填内容：

    python study/tools/render_plan.py
    python study/tools/render_plan.py --check

校验输出不代表实验通过。真实GPU、模型、MPI、Ray或K8S测试需要各自可用环境；未具备条件时记录阅读/设计结果及待测项。当前本机已验证的是CPU学习路径，不把未来的GPU运行写成既成事实。
